# 需求说明

这份文档说明这个工具**要解决什么、不解决什么**，以及判断它是否合格的标准。
写它的目的是让边界清晰 —— 尤其是「不做什么」那一节，它决定了很多设计取舍。

## 背景

同时在多家服务商租 VPS 时，流量额度要分别登各家面板、逐台点开才看得到。
而超额的代价是实打实的：限速或停机。

问题不在于「查不到」，而在于**查这件事太麻烦，所以没人天天查**，
等到想起来看的时候往往已经晚了。

## 目标用户

在两家或以上服务商有 VPS、且流量额度是真实约束的个人用户。
典型场景是几台机器跑代理、备份或小型服务，月流量在配额的 50%–90% 之间浮动 ——
**不会必然超，但也不能不管**。

## 核心场景

1. **每天扫一眼** —— 不打开任何界面，从菜单栏/托盘图标就知道最紧张那台用了多少
2. **月中判断** —— 「按现在这个速度，月底会用到多少？会不会超？」
3. **异常察觉** —— 某台突然跑量（被刷、配置错、进程失控），趋势图上一眼看得出拐点
4. **接入新机器** —— 填几个字段就能纳入监控，不需要在服务器上装 agent

## 功能需求

### 采集

| # | 需求 |
|---|---|
| C1 | 支持 Vultr：调官方 REST API，不需要登录服务器 |
| C2 | 支持任意可 SSH 的服务器：读 `vnstat` 的日统计（DMIT 走这条） |
| C3 | 定时自动采集，周期可配（界面提供 15 / 60 / 360 / 1440 分钟四档） |
| C4 | 支持手动立即刷新 |
| C5 | 并发采集多台；**单台失败不影响其他台**，失败原因可见 |
| C6 | 采集成功但存在隐患时给出提醒（例如服务器时区不是 UTC） |
| C7 | 新增一家服务商的成本 = 实现一个 `Collector`，不改动其他层 |

### 计算

| # | 需求 |
|---|---|
| K1 | 按账单重置日切分账期，`resetDay` 可为 1–31，当月天数不足时回退到月末 |
| K2 | 支持四种计费口径：仅出站 / 仅入站 / 双向求和 / 取较大值 |
| K3 | 支持两种 GB 进制：1024³ 与 1000³ |
| K4 | 按当前平均速度外推账期末总用量，并判断是否会超额 |
| K5 | 账期样本不足半天时不给外推值（而不是给一个被波动放大的假数字） |
| K6 | 支持「起始已用量」补偿，用于账期中途才开始监控的情况；该补偿绑定账期，换账期自动失效 |
| K7 | 配额未知时明确显示「配额未知」，而不是画一个没有意义的进度条 |

### 呈现

| # | 需求 |
|---|---|
| P1 | 常驻系统托盘/菜单栏，图标直接反映**最紧张那台**的用量 |
| P2 | 图标颜色/数字随严重程度变化，不用点开就能感知 |
| P3 | 列表显示每台的已用量、配额、剩余、剩余天数、外推值 |
| P4 | 单台详情显示账期内的每日流量趋势图 |
| P5 | 显示上次成功刷新时间与最近一次的错误原因 |
| P6 | **菜单栏图标不可用时必须有兜底入口**（macOS 会在菜单栏拥挤时静默丢弃状态项） |

### 配置

| # | 需求 |
|---|---|
| G1 | 图形界面完成全部配置，不需要手写 JSON |
| G2 | 配置格式两端完全一致，`config.json` 可直接拷贝 |
| G3 | **API Key 不写入配置文件**（macOS 钥匙串 / Windows DPAPI），配置文件可放心备份 |
| G4 | 提供「测试连接」，接入时能立刻验证凭据、网卡名是否正确 |
| G5 | macOS 另提供命令行诊断工具，绕开 UI 逐项排查 |

### 存储

| # | 需求 |
|---|---|
| S1 | 本地 SQLite 留存历史，不受上游数据窗口（Vultr 约 30 天、vnstat 62 天）限制 |
| S2 | 同一天重复采集是覆盖而非累加 |
| S3 | 某次采集失败时，界面继续显示上次成功的数据 |
| S4 | 数据完全留在本机，不上传任何第三方 |

## 非目标

明确**不做**的事，以及为什么：

- **不做流量对账。** 工具读的是网卡实际收发的字节数或服务商 API 报告的值，
  而计费用的是服务商交换机上的计数，两者通常接近但不会完全相等。
  **定位是提前预警，不是对账** —— 逼近配额时以服务商面板为准。
- **不做自动处置。** 不会自动关机、限速、切流量。判断和操作都留给人 ——
  一个监控工具误判后自动动手的代价，远大于它省下的那点事。
- **不做服务端。** 没有云端账号、没有中心化存储、没有遥测。
  数据留在本机，配置文件用户自己拿得走。
- **不做告警推送。** 邮件/Webhook/IM 通知不在当前范围内。常驻图标本身就是提醒。
- **不在服务器上装 agent。** SSH + vnstat 已经够用，装 agent 会显著抬高接入成本。
- **不支持密码认证的 SSH。** 仅密钥认证。
- **不做移动端。**

## 精度边界

必须写清楚，否则会被当成对账工具用：

- 网卡计数与服务商计费口径存在**系统性差异**（协议开销、内网流量是否计费等）
- vnstat 按服务器本地时区切分自然日，本工具按 UTC 记账，非 UTC 服务器有数小时偏差
- Vultr 的带宽数据是**周期性刷新**的，不是实时值 —— 把刷新周期设成 15 分钟不会让数据更新得更快
- `meterMode` / `unitBase` 填错会造成系统性偏差（前者可能差一倍，后者差 7.4%），
  首次接入**必须**对照服务商面板校准

## 验收标准

一个可用的版本应当满足：

1. 两端都能从零配置到看见真实数字，全程不需要手写 JSON
2. 配置文件在 macOS 与 Windows 之间拷贝后可直接使用
3. 拔掉网线/写错密钥时，界面显示明确的错误原因，且其他正常的机器不受影响
4. 关掉应用一周再打开，历史数据仍在，趋势图连续
5. 账期切换当天，用量归零且起始已用量补偿自动失效
6. `swift test` 全绿；两端计算逻辑对同一份输入给出相同结果
7. 菜单栏图标被系统丢弃时，用户仍有办法打开主窗口
