# 配置文件参考

配置文件是 macOS 与 Windows 两端**共用的同一份格式**，可以在两台机器之间直接拷贝。

| | 位置 |
|---|---|
| macOS | `~/Library/Application Support/VPSTrafficQuota/config.json` |
| Windows | `%APPDATA%\VPSTrafficQuota\config.json` |

数据库（`usage.sqlite`）和密钥文件在同一个目录下。**API Key 不在 config.json 里**，
所以这份文件可以放心备份。

模板见 [`shared/config.example.json`](../shared/config.example.json)。

菜单栏上的剩余流量与面板用同一套换算（≥1 TB 用 T、≥1 GB 用 G、其余用 M），
只是单位缩成一个字母、不留空格：`1.94T`、`576G`、`512M`。其余界面仍用完整写法。

---

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `refreshIntervalMinutes` | int | 自动刷新周期（分钟）。界面提供 15 / 60 / 360 / 1440 四档；手改成小于 5 的值会被强制抬到 5 |
| `servers` | array | 服务器列表，界面按此顺序显示 |
| `menuBarServerId` | string \| 缺省 | 常驻区（macOS 菜单栏 / Windows 托盘）显示哪台服务器的剩余流量，取值是某台服务器的 `id`。缺省或指向一台已删除的服务器时，回退到用量比例最高的那台 |
| `menuBarShowsRemaining` | bool | 常驻区要不要显示剩余流量的文字。`false` 时 macOS 菜单栏只剩图标、Windows 右键菜单不再有那行摘要，图标颜色照常随严重程度变化。缺省 `true` |

## 服务器字段

### 通用

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | **内部唯一标识，也是历史数据的关联键。改了它等于丢掉这台机器的全部历史。** |
| `name` | string | 显示名称，随便起 |
| `provider` | `"vultr"` \| `"ssh"` | 数据来源 |
| `quotaGB` | number | 月配额（GB）。填 `0` 时：Vultr 自动采用 API 报告的值，SSH 则显示「配额未知」 |
| `meterMode` | 见下 | 计费口径 |
| `unitBase` | `"binary"` \| `"decimal"` | GB 进制 |
| `resetDay` | int 1–31 | 每月配额归零的日子 |
| `usageBaseline` | object \| 缺省 | 本账期的「起始已用量」基准，见下 |

### `provider: "vultr"` 专用

| 字段 | 说明 |
|---|---|
| `vultrInstanceId` | 实例 UUID。用 `vpsquota-cli vultr-instances` 列出，或从后台 URL 里取 |

### `provider: "ssh"` 专用

| 字段 | 说明 |
|---|---|
| `sshHost` | 主机名或 IP |
| `sshPort` | 端口，默认 22 |
| `sshUser` | 用户名 |
| `sshKeyPath` | 私钥路径，支持 `~` 开头。留空则交给 ssh 按其自身配置决定 |
| `interface` | vnstat 要统计的网卡名。留空则用 vnstat 返回的第一块网卡 |

---

## `meterMode`：计费口径

| 取值 | 含义 | 典型场景 |
|---|---|---|
| `outbound` | 只算出站（tx） | Vultr；DMIT 的单向流量套餐 |
| `inbound` | 只算入站（rx） | 少见 |
| `sum` | 进出相加 | DMIT 的双向流量套餐 |
| `max` | 逐日取进出中较大者 | 少数服务商 |

**填错的后果**：`sum` 和 `outbound` 之间可能差一倍。程序无法探测，必须你自己确认。

---

## `unitBase`：GB 进制

| 取值 | 含义 |
|---|---|
| `binary` | 1 GB = 1024³ 字节（即 GiB）。**默认值** |
| `decimal` | 1 GB = 1000³ 字节 |

两者相差 **7.4%**。这在用量 30% 时无所谓，但在 90% 时足以决定你会不会误判还剩多少。
各家口径不统一，而且几乎都不写在文档里，所以只能对照面板校准（见下）。

---

## `usageBaseline`：起始已用量基准

```jsonc
"usageBaseline": { "periodStart": "2026-08-10", "usedGB": 320.5 }
```

vnstat 只能统计它自己开始记录之后的流量。**如果在账期中途才装上 vnstat，或它的数据库被重建过**，
本账期前半段的用量本地就永远没有记录，面板会显示得远低于真实值。

这时从服务商面板抄一个当时的已用量填进 `usedGB`，缺口就补上了。界面上对应
「起始已用量 → 开始监控前已用（GB）」。

**`periodStart` 是关键**：它记下这个基准属于哪个账期，只有当前账期与之吻合时才生效。
界面在保存时自动填当前账期的起始日，你不用手填。下个账期一到，这个补偿值自动失效 ——
否则它会变成凭空多出来的流量，一直虚高下去。

Vultr 走 API，返回的是整个账期的完整数据，通常不需要这一项。

---

## `resetDay`：账单重置日

账期是**左闭右开**的 `[本期重置日, 下期重置日)`。

**当月没有该日时取当月最后一天。** 例如 `resetDay: 31`：

| 月份 | 实际重置日 |
|---|---|
| 1 月 | 1-31 |
| 2 月（平年） | 2-28 |
| 2 月（闰年） | 2-29 |
| 4 月 | 4-30 |

这与主流服务商的做法一致。

## 校准流程

`meterMode` 和 `unitBase` 是仅有的两个「程序猜不出、填错会系统性偏差」的字段。
首次配置后务必校准一次：

1. 工具里刷新，记下「已用」
2. 打开服务商面板，看它显示的本月已用
3. 对照：

| 差异 | 结论 | 怎么改 |
|---|---|---|
| 约 2 倍 | 计费口径反了 | `sum` ↔ `outbound` 互换 |
| 约 7% | GB 进制反了 | `binary` ↔ `decimal` 互换 |
| 几个百分点 | 正常 | 不用管 —— 见下 |

### 关于那几个百分点

工具读的是**网卡实际收发的字节数**（vnstat）或**服务商 API 报告的值**，
而计费用的是服务商交换机上的计数。封装开销、计费起止时刻、是否计入内网流量
都会造成小幅差异。

**本工具的定位是提前预警，不是对账。** 逼近配额时请以服务商面板为准。

---

## 时区

所有日期以 **UTC** 存储和计算。

Vultr API 返回的日期键本身就是 UTC，完全对齐。

vnstat 按**服务器本地时区**切分自然日，若服务器不在 UTC，
账期首尾两天会有几小时的归属偏差。工具会自动检测并在界面上提醒；
想彻底对齐就在服务器上执行 `timedatectl set-timezone UTC`。
